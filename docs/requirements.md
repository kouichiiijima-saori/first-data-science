要件定義書
プロジェクト名：はじめてのデータサイエンス

## 1. プロジェクト概要

データサイエンスを初めて学ぶ人に向けて、Python・統計・データ分析・機械学習の基礎を分かりやすく紹介する初心者向け学習サイトを制作する。

管理者はログイン後、Markdown形式で記事の投稿・編集・削除を行うことができる。一般利用者は、公開された記事をログインせず閲覧できる。

制作には Ruby on Rails と MySQL を使用し、記事管理機能付きの動的Webサイトとして開発する。Webアプリ本体の実装言語はRubyとし、Pythonは記事内の学習サンプルとして表示するだけで、サーバーやブラウザ上で実行しない。

## 2. サイト情報

- テーマ: データサイエンス初心者向け学習サイト
- サイトタイトル: はじめてのデータサイエンス
- サブタイトル: Python・統計・データ分析を基礎から学ぶ初心者向け入門サイト
- 制作形式: Ruby on Railsを使用した記事管理機能付きWebサイト
- 記事形式: MarkdownによるQiita風の学習記事

## 3. サイトの目的

- データサイエンス初心者が、基礎知識を順番に学べるようにする
- Python、統計、データ分析、機械学習の概要を分かりやすく伝える
- 専門用語をできるだけ噛み砕いて説明する
- 初心者が次に何を学べばよいか分かる構成にする
- 管理者がプログラムを直接変更せずに記事を更新できるようにする
- Markdownの見出し、表、コードブロック、画像を使い、読みながら学べる記事詳細画面を提供する

## 4. 想定利用者

- データサイエンスを初めて学ぶ人
- Python未経験者または初学者
- 統計やデータ分析に苦手意識がある人
- 将来データ分析を仕事にしたい人
- AIや機械学習に興味がある人

## 5. 利用者区分

### 5.1 一般利用者

一般利用者はログインせずにサイトを利用できる。

一般利用者ができること:

- トップページの閲覧
- 記事一覧の閲覧
- 記事詳細の閲覧
- タグの確認
- 記事内画像の閲覧
- 記事内リンクの利用

管理者ができること:

- 記事の編集
- 記事の削除
- 記事タイトルの登録
- Markdown本文の登録
- タグの登録
- thumbnail画像のアップロード
- 本文画像のアップロード補助

## 6. 機能要件

### 6.1 管理者認証機能

- メールアドレスとパスワードでログインできる
- 管理者IDログインは実装しない
- 管理者登録画面は作らない
- 初期管理者は `db/seeds.rb` で作成する
- パスワードは平文で保存しない
- パスワードはハッシュ化して保存する
- ログインしていない利用者は管理画面へアクセスできない
- ログイン成功後は常に `/admin` へ遷移する
- `return_to` 保存は実装しない
- 管理者はログアウトできる

### 6.2 記事管理機能

管理者は次の操作を行える。

- 記事を新規作成する
- 記事を編集する
- 記事を削除する
- 記事タイトルを設定する
- 記事概要を設定する
- Markdown本文を設定する
- `draft` / `published` の公開状態を設定する
- タグをカンマ区切りで設定する
- thumbnail画像を登録する
- 本文画像を登録し、Markdown画像記法として本文から参照する
- Markdown previewを確認する

### 6.3 記事表示機能

一般利用者は次の情報を閲覧できる。

- 記事タイトル
- 記事概要
- Markdownから安全に変換された記事本文HTML
- 記事画像
- タグ
- 次に読む記事または関連記事へのリンク
- 記事一覧

投稿日は表示しない。一般画面には `published` の記事のみ表示する。

### 6.4 タグ機能

- 記事ごとにタグを設定できる
- タグは複数設定できる
- タグはカンマ区切りで入力できる
- DBは `tags` / `article_tags` に正規化する
- 記事詳細画面にタグを表示する

### 6.5 Markdown本文機能

記事本文はMarkdown原文を `articles.body` に保存する。HTMLへ変換した結果は正本として保存しない。

MVPで対応するMarkdown記法:

- 見出し
- 段落
- 太字
- 箇条書き
- 番号付きリスト
- 引用
- リンク
- 表
- inline code
- fenced code block
- code language指定
- 画像
- 水平線

CommonMarkまたはGitHub Flavored Markdown相当を候補とする。Markdown libraryは設計段階では候補比較までとし、Gem追加は次Step以降で行う。

### 6.6 Qiita風学習記事として扱う表示要素

記事詳細画面はQiitaのように、次を読みながら学べる構成とする。ただしQiitaそのものを再現しない。

- 見出し
- 説明文
- 箇条書き
- 表
- 引用
- リンク
- inline code
- 言語名付きcode block
- 実行結果例
- 画像
- タグ
- まとめ
- 次に読む記事

Pythonコード例と実行結果例はMarkdown本文内に掲載する。ブラウザ上でPythonを実行する機能は作らない。

### 6.7 文字装飾機能

Markdown標準で対応するもの:

- 文字サイズ: 見出し記法で対応
- リンク: Markdown標準
- 画像: Markdown画像記法または専用挿入補助
- code: inline code / fenced code block

Markdown標準では不足するためMVPで限定対応するもの:

- 文字色: あらかじめ許可した1〜2色の限定記法または安全なclassを使用
- 下線: 限定記法または安全な専用classを使用
- 画像サイズ: 小・中・大の3段階のみ

任意HTMLを無制限に許可しない。自由なdrag resize、無制限color picker、任意のstyle属性は実装しない。

### 6.8 画像機能

- Active Storageを使用する
- 記事一覧用thumbnailをアップロードできる
- 記事本文用画像をアップロードできる
- 本文画像はMarkdown画像記法で本文から参照する
- 画像サイズは小・中・大の3段階をMVP候補とする
- 一般利用者が記事内画像を閲覧できる

### 6.9 Preview機能

- 管理者は保存前にMarkdown previewを確認できる
- PreviewはRails側のMarkdown変換・sanitize処理を共通利用する方式を優先する
- real-time previewは時間不足時に簡略化可能とする

### 6.10 レスポンシブ対応

次の画面幅で大きく崩れないようにする。

- パソコン
- タブレット
- スマートフォン

特にスマートフォンで、文字、画像、メニュー、コードブロックが画面外へ大きくはみ出さないようにする。

## 12. 非機能要件

### 12.1 セキュリティ

- パスワードを平文保存しない
- 管理画面への未認証アクセスを防止する
- 入力値の検証を行う
- SQL Injection対策としてRails標準の仕組みを利用する
- CSRF対策としてRails標準機能を利用する
- 画像以外の不正なファイルアップロードを制限する
- Markdown変換後HTMLをそのまま無制限に出力しない
- sanitizeを行う
- `script` tagを許可しない
- event handler属性を許可しない
- `iframe` は原則許可しない
- 任意 `style` 属性は原則許可しない
- 許可するclassを限定する
- linkの危険なschemeを拒否する
- image URLまたはActive Storage参照を安全に扱う
- raw HTMLを許可する場合も許可要素を限定する
- code block内は実行しない
- Python codeをサーバーで実行しない

### 12.2 操作性

- 初心者でも記事を読み進めやすい構成にする
- 管理者が迷わず記事を追加、編集、削除できるようにする
- Markdown本文の入力例を表示する
- Previewで保存前の見え方を確認できる
- ボタン名や入力項目名を分かりやすくする
- エラー内容を画面上に表示する

### 12.3 表示性能

- 通常の閲覧で大きな待ち時間が発生しない
- 画像は必要以上に大きなサイズで表示しない
- 一覧画面に大量の画像を一度に表示しすぎない
- 長いコードブロックは横スクロールまたは折り返しで表示崩れを避ける

### 12.4 保守性

- Railsの標準的なMVC構成を利用する
- Markdown変換とsanitize処理は共通化する
- Controllerへ処理を集中させすぎない
- モデル名、変数名、画面名を分かりやすくする
- READMEに起動方法と初期設定方法を記載する
