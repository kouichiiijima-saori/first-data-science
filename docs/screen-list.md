# 画面一覧

## 前提

- 正本は `docs/requirements.md` とする。
- Ruby on Rails + MySQL + MarkdownによるQiita風学習サイトとして設計する。
- React、Vue、Next.js等の別Frontend frameworkは導入しない。
- JavaScriptはMarkdown previewなどの補助機能に限定する。
- Action Text、Trix editor、`has_rich_text :body` は採用しない。
- 記事本文は `articles.body` にMarkdown原文として保存し、Rails側でHTMLへ変換してsanitize後に表示する。
- 一般利用者向け画面には投稿日を表示しない。
- 一般画面には `published` の記事のみ表示する。
- 404エラーページは画面設計上 `PUB-04` として維持するが、`/404` を通常利用する独立ルートとして必須にはしない。存在しない記事、非公開記事、存在しないURLに対してHTTP 404で表示する。

## トップページと記事一覧ページの扱い

4週間80時間MVPでは、トップページと記事一覧ページを分ける。トップページはサイト説明と主要記事への導線、記事一覧ページは公開記事の一覧に役割を絞る。

実装メモ: 公開記事一覧・詳細Backend実装時点では、一般利用者の入口を動作可能にするため `root` を `ArticlesController#index` へ向ける。トップページ専用のサイト説明・主要記事導線・本格表示調整は後続Taskで実装する。

## 画面数

- 一般利用者向け: 4画面
- 管理者向け: 5画面
- 合計: 9画面

## PUB-01 トップページ

- 画面ID: PUB-01
- 画面名: トップページ
- 想定URL: `/`
- 利用者: 一般利用者
- 認証要否: 不要
- 目的: 「はじめてのデータサイエンス」の概要を伝え、初心者が記事を読み始められるようにする。
- 主な表示項目:
  - サイトタイトル
  - サブタイトル
  - サイトの説明
  - おすすめ記事または主要記事
  - 学習カテゴリ
  - 記事一覧へのリンク
- 主な操作:
  - 記事一覧へ移動
  - 記事詳細へ移動
- 遷移先:
  - `/articles`
  - `/articles/:id`
- エラー表示:
  - 公開記事が未登録の場合は「記事は準備中です」と表示する。
- レスポンシブ上の注意:
  - スマートフォンではサイト説明、記事カード、カテゴリを縦並びにする。
- PDF課題要件との対応関係:
  - トップページの閲覧
  - サイトタイトル・サブタイトル表示

## PUB-02 記事一覧ページ

- 画面ID: PUB-02
- 画面名: 記事一覧ページ
- 想定URL: `/articles`
- 利用者: 一般利用者
- 認証要否: 不要
- 目的: `published` の記事を一覧で表示し、記事詳細へ遷移できるようにする。
- 主な表示項目:
  - 記事タイトル
  - 記事概要
  - タグ
  - thumbnail画像
  - 記事詳細へのリンク
- 主な操作:
  - 記事詳細へ移動
  - トップページへ戻る
- 遷移先:
  - `/articles/:id`
  - `/`
- エラー表示:
  - 公開記事がない場合は「公開中の記事はありません」と表示する。
- レスポンシブ上の注意:
  - PCでは2〜3列のカード表示、スマートフォンでは1列表示を基本とする。
  - 投稿日は表示しない。
  - サムネイル画像領域はカード内で16:9比率を保ち、object-fit: cover で表示する。極端な縦長・横長画像でもカード高さが不自然に伸びないようにする。
  - サムネイル画像がない場合は画像領域を表示しない。
- PDF課題要件との対応関係:
  - 記事一覧の閲覧
  - タグの確認
  - 記事画像の閲覧
  - 投稿日非表示

## PUB-03 記事詳細ページ

- 画面ID: PUB-03
- 画面名: 記事詳細ページ
- 想定URL: `/articles/:id`
- 利用者: 一般利用者
- 認証要否: 不要
- 目的: Markdownから安全に変換されたQiita風の学習記事を閲覧できるようにする。
- 主な表示項目:
  - 記事タイトル
  - Markdownから変換しsanitizeした記事本文HTML
  - 見出し
  - 説明文
  - 箇条書き
  - 表
  - 引用
  - リンク
  - inline code
  - 言語名付きcode block
  - 実行結果例
  - 画像
  - タグ
  - まとめ
  - 次に読む記事または関連記事へのリンク
  - 必要に応じて簡易目次
- 主な操作:
  - 次に読む記事へ移動
  - 記事一覧へ戻る
  - 記事内リンクを開く
- 遷移先:
  - `/articles`
  - `/articles/:id`
  - 記事本文内リンク先
- エラー表示:
  - 存在しない記事ID、非公開記事、削除済み記事の場合はHTTP 404でエラーページを表示する。
- レスポンシブ上の注意:
  - 本文幅を読みやすい幅に制限する。
  - code blockは横スクロールまたは折り返しで表示崩れを避ける。
  - 画像は親要素の幅を超えないようにする。
  - サムネイル画像は max-height: 500px で制限し、object-fit: contain で画像全体を表示して中央配置する。
  - サムネイル画像がない場合は画像領域を表示しない。
  - syntax highlightingは候補だが、80時間MVPの必須機能にはしない。
- PDF課題要件との対応関係:
  - 記事詳細の閲覧
  - 記事本文の閲覧
  - 画像閲覧
  - タグ表示
  - 関連記事へのリンク
  - 投稿日非表示

## PUB-04 404エラーページ

- 画面ID: PUB-04
- 画面名: 404エラーページ
- 想定URL: HTTP 404。`/404` を通常利用する独立ルートとして必須にはしない。
- 利用者: 一般利用者
- 認証要否: 不要
- 目的: 存在しないURL、存在しない記事、非公開記事にアクセスした利用者を適切な画面へ誘導する。
- 主な表示項目:
  - エラーメッセージ
  - トップページへのリンク
  - 記事一覧へのリンク
- 主な操作:
  - トップページへ戻る
  - 記事一覧へ戻る
- 遷移先:
  - `/`
  - `/articles`
- エラー表示:
  - 404画面自体では追加のエラー表示は行わない。
- レスポンシブ上の注意:
  - 時間不足時は装飾を縮小し、必要な案内表示を優先する。
- PDF課題要件との対応関係:
  - 404エラーページ

## ADM-04 記事新規作成ページ

- 画面ID: ADM-04
- 画面名: 記事新規作成ページ
- 想定URL: `/admin/articles/new`
- 利用者: 管理者
- 認証要否: 必要
- 目的: 管理者がMarkdown形式で新しい記事を登録する。
- 主な表示項目:
  - 記事タイトル入力欄
  - 記事概要入力欄
  - Markdown本文textarea
  - Markdown記法の簡易ヘルプ
  - code block入力例
  - 実行結果入力例
  - タグ入力欄
  - 公開状態入力欄
  - thumbnail upload
  - 本文画像upload補助
  - Preview buttonまたはpreview領域
  - sanitize後のpreview表示
  - 保存ボタン
  - キャンセルリンク
- 主な操作:
  - 保存
  - キャンセル
  - Markdown preview
  - 本文画像upload
  - 生成されたMarkdown画像記法のcopyまたは挿入

  - 保存成功時: `/admin/articles`

  - タイトル未入力
  - 概要未入力
  - 本文未入力

  - textarea、preview、画像upload欄が横にはみ出さないようにする。
- PDF課題要件との対応関係:
  - 記事新規作成
  - タイトル・本文・タグ登録
  - 画像アップロード
  - 本文装飾
  - 1記事400文字以上

## 認証対象画面

認証が必要な画面は以下の4画面とする。

- ADM-02 管理画面トップ
- ADM-03 記事管理一覧ページ
- ADM-04 記事新規作成ページ
- ADM-05 記事編集ページ

`ADM-01 管理者ログインページ` は未ログイン状態で表示するため認証不要とする。

## 設計上の注意

- 管理者の新規登録画面は作らず、初期管理者は `db/seeds.rb` で作成する。ログインIDはメールアドレスとし、管理者IDログインは実装しない。
- 一般利用者向け記事詳細は `published` の記事のみ表示する。
- 管理者画面では内部管理用として更新日時を表示してよいが、一般利用者向け画面には投稿日を表示しない。
- 削除はMVPでは物理削除を推奨する。ただし削除前に確認ダイアログを必須にする。
- 簡易目次は候補とし、80時間を超える場合は手動Markdownリンクまたは目次なしへ簡略化する。
