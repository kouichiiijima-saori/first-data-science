# 画面一覧

## 前提

- 正本は `docs/requirements.md` とする。
- 今回は実装前の初期設計であり、`routes.rb`、Controller、View、CSS、JavaScript は作成しない。
- URLは Rails の RESTful routing を優先した案であり、実装時に最終確定する。
- 404エラーページは画面設計上 `PUB-04` として維持するが、`/404` を通常利用する独立ルートとして必須にはしない。存在しない記事、非公開記事、存在しないURLに対してHTTP 404で表示する。
- 一般利用者向け画面には投稿日を表示しない。`created_at` / `updated_at` はDBの内部管理用として保持する。
- 管理者画面はログイン済み管理者のみ利用できる。
- PDF課題要件との対応関係は、要件定義書の完成条件・機能要件との対応を示す。

## トップページと記事一覧ページの扱い

### 案A: トップページと記事一覧ページを分ける

- `/` はサイト紹介、おすすめ記事、学習カテゴリ、主要記事への導線を配置する。
- `/articles` は公開記事を一覧表示する。
- 役割が明確で、学習サイトとしての導入と記事一覧を分けやすい。
- 画面数は増えるが、要件定義書の画面一覧と一致する。

### 案B: トップページ内に記事一覧を含める

- `/` にサイト紹介と記事一覧をまとめる。
- 実装画面数は少なくなる。
- ただし、要件定義書に「トップページ」「記事一覧ページ」が別画面として記載されているため、課題確認時に画面不足と見られる可能性がある。

### 推奨

4週間MVPでは **案A: トップページと記事一覧ページを分ける** ことを推奨する。理由は、要件定義書と対応しやすく、トップページは少数のおすすめ・主要記事、記事一覧ページは全記事一覧という役割分担にできるため。実装工数を抑えるため、トップページの記事表示は最大3〜5件程度の簡易表示にする。

## 画面数

- 一般利用者向け: 4画面
- 管理者向け: 5画面
- 合計: 9画面

## PUB-01 トップページ

- 画面ID: PUB-01
- 画面名: トップページ
- 想定URL: `/`
- 利用者: 一般利用者
- 認証要否: 不要
- 目的: 「はじめてのデータサイエンス」の概要を伝え、初心者が記事を読み始められるようにする。
- 主な表示項目:
  - サイトタイトル
  - サブタイトル
  - サイトの説明
  - おすすめ記事または主要記事
  - 学習カテゴリ
  - 記事一覧へのリンク
- 主な操作:
  - 記事一覧へ移動
  - 記事詳細へ移動
- 遷移先:
  - `/articles`
  - `/articles/:id`
- エラー表示:
  - 記事が未登録の場合は「記事は準備中です」と表示する。
- レスポンシブ上の注意:
  - スマートフォンではサイト説明、記事カード、カテゴリを縦並びにする。
  - 画像やカードが画面外へはみ出さないようにする。
- PDF課題要件との対応関係:
  - トップページの閲覧
  - サイトタイトル・サブタイトル表示
  - 初心者向け学習サイトとしての導線

## PUB-02 記事一覧ページ

- 画面ID: PUB-02
- 画面名: 記事一覧ページ
- 想定URL: `/articles`
- 利用者: 一般利用者
- 認証要否: 不要
- 目的: 公開済み記事を一覧で表示し、記事詳細へ遷移できるようにする。
- 主な表示項目:
  - 記事タイトル
  - 記事概要
  - タグ
  - 一覧用画像
  - 記事詳細へのリンク
- 主な操作:
  - 記事詳細へ移動
  - トップページへ戻る
- 遷移先:
  - `/articles/:id`
  - `/`
- エラー表示:
  - 公開記事がない場合は「公開中の記事はありません」と表示する。
- レスポンシブ上の注意:
  - PCでは2〜3列のカード表示、スマートフォンでは1列表示を基本とする。
  - 投稿日は表示しない。
- PDF課題要件との対応関係:
  - 記事一覧の閲覧
  - タグの確認
  - 記事画像の閲覧
  - 投稿日非表示
  - レスポンシブ対応

## PUB-03 記事詳細ページ

- 画面ID: PUB-03
- 画面名: 記事詳細ページ
- 想定URL: `/articles/:id`
- 利用者: 一般利用者
- 認証要否: 不要
- 目的: 記事本文、画像、タグ、関連記事を閲覧できるようにする。
- 主な表示項目:
  - 記事タイトル
  - 記事本文
  - 本文内画像
  - タグ
  - 関連記事へのリンク
  - 記事一覧へ戻るリンク
- 主な操作:
  - 関連記事へ移動
  - 記事一覧へ戻る
  - 記事内リンクを開く
- 遷移先:

  - 画像は親要素の幅を超えないようにする。
  - 文字色・文字サイズ・下線が小画面で読みにくくならないようにする。
- PDF課題要件との対応関係:

  - 記事本文の閲覧

  - タグ表示
  - 関連記事へのリンク
  - 投稿日非表示

## PUB-04 404エラーページ

- 画面ID: PUB-04
- 画面名: 404エラーページ
- 想定URL: HTTP 404。`/404` を通常利用する独立ルートとして必須にはしない。
- 利用者: 一般利用者
- 認証要否: 不要
- 目的: 存在しないURLや記事にアクセスした利用者を適切な画面へ誘導する。
- 主な表示項目:
  - エラーメッセージ
  - トップページへのリンク
  - 記事一覧へのリンク
- 主な操作:
  - トップページへ戻る
  - 記事一覧へ戻る
- 遷移先:
  - `/`
  - `/articles`
- エラー表示:
  - 404画面自体では追加のエラー表示は行わない。
- レスポンシブ上の注意:
  - メッセージとリンクを中央寄せまたは読みやすい縦並びにする。
- PDF課題要件との対応関係:
  - 404エラーページ
  - 操作性の確保

- 画面ID: ADM-03
- 画面名: 記事管理一覧ページ
- 想定URL: `/admin/articles`
- 利用者: 管理者
- 認証要否: 必要
- 目的: 登録済み記事を確認し、新規作成、編集、削除を行えるようにする。
- 主な表示項目:
  - 記事タイトル
  - 公開状態
  - タグ
  - 更新日時
  - 編集ボタン
  - 削除ボタン
  - 新規作成ボタン
- 主な操作:

## ADM-04 記事新規作成ページ

- 画面ID: ADM-04
- 画面名: 記事新規作成ページ
- 想定URL: `/admin/articles/new`
- 利用者: 管理者
- 認証要否: 必要
- 目的: 管理者が新しい記事を登録する。
- 主な表示項目:
  - 記事タイトル入力欄
  - 記事概要入力欄
  - 本文エディタ
  - タグ入力欄
  - 一覧用画像アップロード欄
  - 公開状態入力欄
  - 保存ボタン
  - キャンセルリンク
- 主な操作:
  - 保存
  - キャンセル
  - 本文への画像挿入
  - 本文装飾
- 遷移先:
  - 保存成功時: `/admin/articles`
  - キャンセル時: `/admin/articles`
  - 入力エラー時: `/admin/articles/new`
- エラー表示:
  - タイトル未入力
  - 本文未入力

  - タグ形式不正
  - 画像形式・容量不正

  - 管理画面もスマートフォンで大きく崩れないようにするが、本文編集はPC利用を主想定にする。

- PDF課題要件との対応関係:
  - 記事新規作成
  - タイトル・本文・タグ登録
  - 画像アップロード
  - 本文装飾
  - 1記事400文字以上

## 認証対象画面

認証が必要な画面は以下の4画面とする。

- ADM-02 管理画面トップ
- ADM-03 記事管理一覧ページ
- ADM-04 記事新規作成ページ
- ADM-05 記事編集ページ

`ADM-01 管理者ログインページ` は未ログイン状態で表示するため認証不要とする。

## 設計上の注意

- 管理者の新規登録画面は作らず、初期管理者は `db/seeds.rb` で作成する。ログインIDはメールアドレスとし、管理者IDログインは実装しない。
- 一般利用者向け記事詳細は公開済み記事のみ表示する。
- 管理者画面では内部管理用として更新日時を表示してよいが、一般利用者向け画面には投稿日を表示しない。
- 削除はMVPでは物理削除を推奨する。ただし削除前に確認ダイアログを必須にする。
- 404エラーページは第4週の仕上げで実装するが、画面設計上は初期から用意する。時間不足時は装飾を縮小し、HTTP 404として必要な案内表示を優先する。
